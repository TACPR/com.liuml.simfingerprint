# SIM 指纹登录

面向 LSPosed 的本地安全模块：当已验证的中国移动 SIM 登录提示出现在系统 SIM 卡工具包中时，使用强指纹解锁 Android Keystore 加密保存的六位 SIM PIN，并通过 STK 原生输入框和确认按钮提交。

## 当前兼容范围

- PJD110 / Android 15 / ColorOS 15.0.0.502
- `com.android.stk` 15.1.30（versionCode 15001030）
- `com.android.stk.StkInputActivity`
- SIM 卡 1
- 卡一的 STK 原生密码输入页（不限制提示文案）

系统或 STK 版本变化、设备型号未知或选择卡二时会拒绝自动提交；当前版本不宣称适配其他品牌或双卡组合。

## 使用

1. 安装 APK，在 LSPosed 中启用模块。
2. 作用域只选择“电话服务” (`com.android.phone`) 后重启手机。该设备若同时选择 STK 与 Phone，会在同一进程重复加载模块。
3. 打开模块，录入两次六位 SIM PIN，并完成一次强指纹验证。
4. 触发普通 SIM 登录；指纹成功后模块会填入 PIN 并点击 STK 原生确认按钮。
5. 管理页无 Hook 心跳时，确认只勾选 `com.android.phone`，然后重启手机再测试。

## 安全设计

- 无网络权限，禁止应用备份。
- PIN 仅以 AES-GCM 密文落盘；Keystore 密钥要求每次使用强指纹。
- 新增或删除指纹会使密钥失效。
- 前台 STK 页直接按需启动指纹 Activity，无需模块应用常驻后台。
- STK 与指纹 Activity 之间使用随机一次性会话和 Binder 回调；PIN 不放入普通 Intent、广播、文件或日志。
- 每个 STK Activity 最多自动提交一次，并有 60 秒全局防重。
- 诊断日志不记录 PIN、手机号、SIM 标识或完整提示文案。

## 用户协议与风险提示

本模块仅供设备所有者在本人设备、本人账号和已获授权的 SIM 卡上使用，用于辅助系统 SIM 认证；不会绕过 SIM 卡、运营商或业务应用的认证，也不代替运营商或应用方的授权流程。使用者须自行确认单位制度、账号条款及当地法律允许此用途，并自行承担账号、资金、隐私、设备安全和合规风险。

SIM PIN 仅以 Android Keystore 加密密文保存，且每次使用需要强生物识别验证；但系统、指纹、LSPosed、STK、模块或第三方软件异常仍可能造成认证失败、重复操作或其他不可预期结果。模块不保证任何厂商、系统版本、双卡组合或应用的兼容性、可用性和业务结果，不提供运营商官方支持，也不承诺法律不允许排除的责任可以被排除。

模块不申请网络权限，不上传 PIN、手机号、SIM 标识或认证内容。请勿录入他人的 SIM PIN；发现设备、系统或 STK 升级后，应重新完成兼容性检查和真实登录回归。


编译通过不等于 SIM 登录链路验证完成。发布前需在上述真机环境完成成功、取消、错误 PIN、防重、超时、重启和非登录负向测试。

## 扩展适配流程

其他品牌或双卡设备目前只做兼容性探测，不会自动填充或点击确认。取得测试机后，应先记录设备型号、系统版本、STK 包名/版本、实际进程和卡槽字段，再为该组合新增明确的 `CompatibilityProfile`；不能仅因类名相同就放开自动提交。

每个新配置至少要回归：卡一/卡二分别登录、普通 STK 菜单、取消指纹、错误 PIN、防重复提交、切后台、旋转、进程重启和新增指纹后的密钥失效。完成真实登录回归后，才可将对应卡槽从“未验证”改为可用。
